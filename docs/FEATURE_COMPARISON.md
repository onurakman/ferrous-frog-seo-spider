# SEO Crawler Feature Comparison

Reviewed on 2026-09-09 against the working source, Rust tests, a production frontend build and the real React screen exercised with Tauri IPC fixtures. This is a capability comparison, not a claim of feature parity or a comparison of measured crawl speed.

The reference product publishes a broad [feature overview](https://www.screamingfrog.co.uk/seo-spider/) and documents category tabs, filters, lower-window URL/link details and overview panels in its [user guide](https://www.screamingfrog.co.uk/seo-spider/user-guide/). Ferrous Frog already implements much of the basic crawler pipeline. The largest immediate gaps were unreliable audit classification and incomplete access to existing results.

| Area | Screaming Frog SEO Spider | Ferrous Frog after this repair |
| --- | --- | --- |
| Spider and List crawls | Both modes, configurable discovery | Both modes; pasted URLs, files and sitemap lists. List inputs retain duplicate occurrences and their original order; file import appends occurrences to the Settings draft. |
| Politeness | Robots and configurable crawl speed | Robots on by default, per-origin rules, shared request spacing, bounded retries, pause/stop and Retry-After on Rust HTTP 429/503. Rules apply to redirects and sitemaps; browser requests honor observed cooldowns, but browser response headers do not supply them. |
| Response codes and redirects | Errors, chains and loops | Status families, failures, source links and full followed chains. A stored row combines the requested URL with its final response; intermediate hops are not separate result rows. |
| Titles, descriptions and headings | Missing, duplicate, size and multiple-tag checks | Missing/duplicate/length filters, multiple-title/description warnings, measured tag and heading counts, and estimated pixel widths. Failed/incomplete responses and non-HTML resources are excluded. Old crawls keep unknown title/description counts until recrawled. |
| Indexability and canonicals | Meta/header directives, canonicals and validation | Generic noindex/none, repeated robots tags/headers, HTTP status precedence and HTML/HTTP Link canonicals including PDFs. Target error/redirect/non-indexable/uncrawled, chain and loop audits preserve redirect/List evidence. Unknown cross-host scope, bot-specific precedence and conflicting-signal reports remain incomplete. |
| Results workspace | Category/filter tables and contextual details | Grouped audit views, virtualized 500-row pages, server-side search/sort and All/Any filter groups, individual columns/order/named layouts, multi-row selection, URL details and direct inlink/outlink access. Grid/tree/export filters stay consistent. |
| Link diagnostics | Inlinks, outlinks, anchor text and bulk reports | Stored edges with sources, anchors, positions, nofollow, status and paths. Link/anchor/redirect/sitemap reports now paginate beyond 500 rows. Unknown and robots-blocked targets are separated from known failures. |
| Images and resources | Image/resource crawling and audits | Optional image/CSS/JS/external crawling, alt checks, image references and dimensions. Default-off canonical/hreflang/pagination/AMP/meta-refresh/iframe discovery follows Spider request and scope rules without changing hyperlink counts. External checks honor the opt-in without expanding external pages; internal/external nofollow choices are separate. SimHash clusters, configurable content regions and a pasted-HTML preview control near-duplicate/text analysis. Duplicate/regex/hreflang filters and image/sitemap report paging run in SQL. Record revisions preserve summary/reference caches across frontier-only writes. ## Repairs made

- The UI keeps one bounded result page, refreshes storage queries during a crawl and rejects stale responses. Duplicate and cross-page filters now use the same engine logic during and after crawling.
- Audit categories are navigable from a grouped sidebar or a compact selector. Relevant columns place the current evidence near the URL; all existing columns remain available.
- Link reports have the same page controls as the main grid. Original URLs are visible separately from final URLs, including links into redirects.
- Robots decisions use the target origin, including scheme and port. Concurrent requests share pacing, and unavailable robots policies fail conservatively. Known exclusions do not inflate broken-link counts.
- On-page audit eligibility and known network failures share predicates across typed analysis, memory storage, SQLite summaries/queries, the tree and HTML reports.
- HTML parsing cannot make an HTTP error indexable. Generic directives apply to non-HTML responses too, and page-level nofollow uses the configured link-following choice.
- Heavy row, image, link, anchor and sitemap-validation queries run off the desktop UI thread and propagate storage failures. Image aliases reuse an evidence-revision cache across result/export pages; image references stay live. Sitemap validation still loads records before paging. Fatal crawl errors restore the Start control.
- The launcher is centered above an initially collapsed bottom history panel whose open/closed preference persists. Opening, deleting or importing a crawl clears the previous URL selection, page and progress; session switching is disabled during an active crawl. Screen, drawer and component transitions respect reduced motion.
- The UX follow-up adds direct Settings access, Enter-to-start, filter recovery, pinned URL cells on wide grids and keyboard-accessible detail sections. Dialog actions display feedback inside the active dialog; an empty filter no longer disables whole-crawl exports. Secondary text and error colors are clearer in both themes, and duplicate overview counters were removed.
- Appearance offers System, Light and Dark, defaulting to the system on first launch and following live OS changes. Explicit preferences are remembered and applied before the app loads. The dark palette uses softer charcoal surfaces; graph colors follow the same tokens and update while open. The redesigned splash follows the same appearance, respects reduced motion and remains visible for at least 2.2 seconds during normal startup.
- The compact workbench puts category navigation above 28-pixel virtual rows, preserves a bottom URL inspector and moves progress into the status bar. Inlinks/outlinks stay in the workspace with server-side paging, search, sorting, selection cancellation and retry. Right-side Overview/Issues tabs provide summary drill-down; issue counts cover available summary checks and can overlap. The full audit tree and report dialogs remain available.
- Persisted toolbar scope presets cover current host, start folder, all subdomains with public/private suffix boundaries, and exact URL. Mode keeps separate Spider/List addresses and opens archive comparison or bounded offline snippet CSV editing without changing crawl results.
- Settings has an indented navigation tree that starts collapsed, fixed search that expands matches, a grouped section picker for narrow windows and an Apply/Cancel/OK draft. Changing sections resets form scrolling. Validation and failed saves preserve active preferences. Profile loads respect the latest selection; cancelled requests cannot publish late results or errors. Session/database/archive changes serialize and lock editing until complete.

## Verification and remaining priorities

Verification covers the Rust workspace tests, formatting, Clippy, the production frontend build and headless UI checks. The optional rendering path has compilation, browser discovery and real Chrome HTTP fixture checks. Optional WebGL and snippet tools load on demand; the UI smoke check enforces a 500 kB limit for each production JavaScript chunk without raising the build warning threshold.

Run `make verify`, `make test-ui` and `make check-js-rendering`. The UI check launches a temporary Vite server and headless Chrome, injects the installed Tauri IPC mock, and exercises the real screen. It verifies access past 1,000 URLs and 500 links, filter resets, stale-response ordering, live duplicate views, fatal errors, details, graph exclusions, themes, small-screen layout and selection cleanup when switching databases. It does not replace native desktop end-to-end testing or a large-site benchmark.

The 2026-09-09 rendering follow-up adds capability detection, invalid-path handling, saved-option recovery and checks before starting a crawl. Real-browser fixtures additionally verify HTTP politeness, User-Agent, cross-site frames, dedicated/service workers, popups, redirects and Pause/Resume/Stop via `make test-rendering`. Pause abandons unfinished browser renders; Resume reloads them without recording a timeout during a long pause. Native packaged-app checks on each OS remain open.

Prioritize complete URL/redirect identity reporting, indexability/canonical edge cases, and SQLite query/frontier performance before adding more provider integrations. The pre-existing broad roadmap remains useful, but a feature appearing in Settings is not evidence of complete implementation.
